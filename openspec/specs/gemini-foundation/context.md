# Foundation context

The owner explicitly requested copying the original stack, builds and functionality, rather than rewriting a smaller gateway. The foundation is Soju06/codex-lb at `f8ffbac2099a113fba54dfd8d77774f5bca80ffa`. Its MIT license remains in LICENSE. Original release metadata and internal `codex-lb` package/module/build names are intentionally retained; the `gemini-lb` and `gemini-lb-db` entry points are aliases, not a separately published distribution.

Counting tracked source/configuration files by extension (Python, TypeScript/JavaScript, Rust, shell, CSS, SQL, Nix, C/C++, Go, YAML and TOML), excluding `docs/`, `openspec/`, JSON, locks and downloaded dependencies, the pinned upstream contains 791,062 physical lines and this fork contains 797,677. A 500,000-line target is not a reason to delete regression coverage. All 720 upstream Python/frontend test and screenshot-fixture files remain present. The pre-adoption Node implementation remains in repository history.

Dither Kit source components were imported from the Tripwire registry; `frontend/dither-kit.json` records versions and hashes, and `frontend/src/components/dither-kit/NOTICE` retains the component notice. The existing React forms, navigation, shadcn controls and chart data are retained. No separate UI service is introduced.

Native Google uses the retained model-source control plane, downstream API-key reservations, admission limits and request logging. Its upstream credentials are not Codex accounts. The retained OpenAI routes do not translate Gemini. Dollar limits require explicitly configured model prices; Codex credit limits and OpenAI reasoning/service-tier policies are rejected on native Google requests rather than silently ignored. API-key quota cannot be inferred reliably. Code Assist quota reflects observations, not a live guarantee.

Example: two Google API keys in one quota project should use JSON credentials with the same `quota_scope`; a 429 cooldown then applies to both sources. OAuth tokens must include the matching OAuth client and an already onboarded project. Operator reimport wins over a concurrent refresh through an encrypted-credential compare-and-swap.

Resource lifecycle APIs, automatic project onboarding, paid-credit activation, implicit OpenAI conversion, and translation of the old 0.1 admin API are deliberately unsupported. `/healthz`, inference paths, custom client/session/source headers and existing key hashes are preserved. Import maps legacy accounts to model sources, brings over key assignments and ownership, and copies metadata-only history; it does not fabricate missing historical token breakdowns or costs. Existing credentials are re-encrypted for the copied runtime.

Upstream publication, bot, metadata-update and release workflows are preserved byte-for-byte in `.github/upstream-workflows/`, outside the Actions execution directory. The active workflow validates only and has read-only repository permissions. No package, image, release, production service or migration is published/applied implicitly.

Primary Accounts and Dashboard now use encrypted Google model sources; the retained Codex pages are explicitly available at `/legacy/accounts` and `/legacy/dashboard`. Google connection uses the official Gemini CLI public installed-client identity, its remote authorization-code landing page, and S256 PKCE. Connection resolves an existing project using `loadCodeAssist`, without automatic onboarding, project creation, billing or paid-credit opt-in. For example, a previously onboarded operator signs into Google, pastes its authorization code, and registers a renewable encrypted Code Assist source; an account needing setup is instead directed to finish official CLI setup. Model IDs are operator-supplied rather than an invented Google catalog. The primary dashboard exposes source health and observed Google quota, not Codex credit windows.

Guided registration now allows model-less Google sources, excluded from downstream selection until models are configured. An explicit saved-source metadata check reads the paginated API-key catalog or an existing Code Assist project's observed quota IDs. For example, an API-key operator connects without guessing IDs, discovers the actual catalog and adds Gemini Pro without changing an existing disabled Flash model. Code Assist observations are not a complete catalog or inference-access proof; tools and vision are not guessed.

The personal-account update separates Antigravity from enterprise Code Assist. Google's May 19, 2026 announcement ended consumer Gemini CLI/Code Assist access on June 18, 2026 and directs free/AI Pro users to Antigravity. Personal native clients use `/antigravity`; existing API-key and enterprise paths remain unchanged. The adapter follows CLIProxyAPI's private protocol, with its MIT notice included in the module and packaged artifacts. This is not a Google-supported OAuth gateway contract, and model observations do not establish subscription entitlement or continued compatibility.

Server-only installed-client configuration seeds encrypted per-source refresh credentials. Login uses PKCE, a session-bound ten-minute ticket and a complete state-validated localhost callback URL. An explicit opt-in may request Google-offered free initialization; no paid onboarding, billing activation or paid-credit spending is enabled. Terms/privacy/validation gates remain external. Example: a Pro operator connects the subscribed account, discovers actual model IDs, creates a gateway key, then configures Gemini CLI with that key and `GOOGLE_GEMINI_BASE_URL=https://gemini.mvtp.cloud/antigravity`; a free operator follows the same flow, with Google determining available limits.

Ordinary and SSE generation unwrap the native response and persist input/output/cache/thinking tokens. Repeated cumulative usage is not summed, partial streams settle delivered usage and never replay. A first-user-content hash keeps native appended histories on their original account, scoped by gateway key/provider. Use an explicit unique session header to distinguish identical prompts and retain ownership across compaction. Local HTTP regressions, all 1,662 frontend tests, ten real-backend browser cases, lint/types and packaging passed; actual Google authorization/inference and delivery are tracked separately in the active personal-account change.
