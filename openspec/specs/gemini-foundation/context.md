# Foundation context

The owner explicitly requested copying the original stack, builds and functionality, rather than rewriting a smaller gateway. The foundation is Soju06/codex-lb at `f8ffbac2099a113fba54dfd8d77774f5bca80ffa`. Its MIT license remains in LICENSE. Original release metadata and internal `codex-lb` package/module/build names are intentionally retained; the `gemini-lb` and `gemini-lb-db` entry points are aliases, not a separately published distribution.

Counting tracked source/configuration files by extension (Python, TypeScript/JavaScript, Rust, shell, CSS, SQL, Nix, C/C++, Go, YAML and TOML), excluding `docs/`, `openspec/`, JSON, locks and downloaded dependencies, the pinned upstream contains 791,062 physical lines and this fork contains 797,673. A 500,000-line target is not a reason to delete regression coverage. The pre-adoption Node implementation remains in repository history.

Dither Kit source components were imported from the Tripwire registry; `frontend/dither-kit.json` records versions and hashes, and `frontend/src/components/dither-kit/NOTICE` retains the component notice. The existing React forms, navigation, shadcn controls and chart data are retained. No separate UI service is introduced.

Native Google uses the retained model-source control plane, downstream API-key reservations, admission limits and request logging. Its upstream credentials are not Codex accounts. The retained OpenAI routes do not translate Gemini. Dollar limits require explicitly configured model prices; Codex credit limits and OpenAI reasoning/service-tier policies are rejected on native Google requests rather than silently ignored. API-key quota cannot be inferred reliably. Code Assist quota reflects observations, not a live guarantee.

Example: two Google API keys in one quota project should use JSON credentials with the same `quota_scope`; a 429 cooldown then applies to both sources. OAuth tokens must include the matching OAuth client and an already onboarded project. Operator reimport wins over a concurrent refresh through an encrypted-credential compare-and-swap.

Resource lifecycle APIs, automatic project onboarding, paid-credit activation, implicit OpenAI conversion, and translation of the old 0.1 admin API are deliberately unsupported. `/healthz`, inference paths, custom client/session/source headers and existing key hashes are preserved. Import maps legacy accounts to model sources, brings over key assignments and ownership, and copies metadata-only history; it does not fabricate missing historical token breakdowns or costs. Existing credentials are re-encrypted for the copied runtime.

Upstream publication, bot, metadata-update and release workflows are preserved byte-for-byte in `.github/upstream-workflows/`, outside the Actions execution directory. The active workflow validates only and has read-only repository permissions. No package, image, release, production service or migration is published/applied implicitly.

Local checks passed for lint, types, packaged frontend assets, 1,652 frontend tests and eight real-API browser smoke cases. The corrective pass also passed 60 native/OpenAPI/bulkhead/workflow regressions and 177 dashboard, permission, model-source, native and legacy-import cases. Two shutdown tests failed on the untouched upstream Python 3.14 baseline and are recorded as existing failures, not suppressed; the initial GitHub Python 3.13 run passed these cases.

Rendered fixture checks cover light/dark dashboards, the last row of a 40-account list with help closed/open, and desktop/mobile Code Assist edit dialogs with quota observations, refresh failures and scrolled-to-bottom Save controls. Refresh failure retains the prior 75% observation. The original screenshot suite's two account bottom-gap assertions also fail unchanged upstream at the same 89.5px gap; account scrolling and last-row accessibility passed. Truncated table cells and scrollable forms retain the upstream layout, rather than removing data or controls to satisfy a screenshot.

The foundation and native implementation were published to `deploy103/gemini-lb` through Windows. Initial cloud failures on header-less ASGI scopes, OpenAPI uniqueness, workflow fixture paths, copied CI gates and a removed Docker example were repaired rather than excluded. Full upstream CI gates are restored, including Docker/Trivy, Helm/kind and Nix. Corrective run [38224912451](https://github.com/deploy103/gemini-lb/actions/runs/38224912451) passed every functional/build job, including all core shards, PostgreSQL/native, browser, Rust, Helm/kind and Nix. Docker built successfully but its security gate found HIGH urllib3 2.7.0 advisories CVE-2026-97687 and CVE-2026-97689. The follow-up raises the dependency floor and lock to 2.8.0 using the Docker-pinned uv 0.12.19; 48 native/networking regressions and lint/types pass locally, while the cloud security recheck remains pending. Automated dependency configuration is archived to avoid unsolicited future bot changes; already-created bot PRs are left untouched.

Native regression cases use the real FastAPI application and local HTTP Google/OAuth fixtures; they do not prove access to a live Google account. Docker execution requires a usable Docker daemon and was unavailable on the local runner. No production data was imported or migrated.
